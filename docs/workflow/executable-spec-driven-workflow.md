# 実行可能仕様駆動開発（executable-spec-driven）ワークフロー
## 前提
- Web開発を前提とする
- ドキュメントではなく実際のコードを正とする
  - ドキュメントはあくまで補助
- AIに与える以下の情報を事前準備する
  - 技術スタック・バージョン
  - プロジェクト構造・ディレクトリ構成
  - 命名規則・コーディング規約
  - 既存コードのパターン・慣例
  - 使用ライブラリ・ツール
- 技術スタックは以下を前提とする
  - フロント
    - React※メタフレームワーク（Next.JS、React Router等）は関係ない
    - Storybook
    - Vitest
    - React Testing Library
  - バックエンド
    - 指定なし
      - FastAPIのようにOpenAPI specを自動生成されるものだと楽
      - 自動生成されない場合はOpenAPI specをYAMLで作成する

## コンセプト
- 実行可能仕様駆動開発（executable-spec-driven）という開発手法を新たに定義
- 実行可能な仕様をまず最初に確定させてそれを中心に機能を開発していく
  - 実行可能な仕様＝実装前に確定させるシステムの仕様・契約
  - 該当するもの
    - 静的画面（Storybook）
    - APIリクエスト・レスポンスのOpenAPI定義
    - ログの形式・出力条件
    - 非同期メッセージ・イベント定義（該当する場合）
    - DBスキーマ（マイグレーション定義）
- アプリのテストコード=仕様書とする
  - ドキュメントは理解を簡単にするための補助とする

## 手順
1. issue作成（`/create-issue`）
   1. AIまたは人間がissueを作成する
2. 要件定義（`/dev-requirements <issue番号>`）
   1. AIがissueを確認
      1. 機能要件・制約の不明点があれば人間に確認する
      2. フィードバック内容をissueにコメントで残す
   2. AIが既存コードベースの調査を行う
   3. AIが仕様を生成する
      1. ドキュメント更新も行う
   4. 人間が仕様を確認する
   5. AIと人間が相談して仕様を確定させる
      1. フィードバック内容をissueにコメントで残す
3. 実装準備（`/dev-impl-prep <issue番号>`）
   1. AIがテスト計画を箇条書きで作成する
   2. 人間がテスト計画を確認・承認する
      1. フィードバックを受けて修正する（複数回対応）
      2. 承認済みテスト計画をissueにコメントで残す
   3. AIがテストを実装する
4. 実装（`/dev-impl <issue番号>`）
   1. AIが補助テストを記載する
      1. 疎結合な設計を保つためのテスト
   2. AIによる実装
   3. AIによるセルフレビュー
      1. セルフレビュー結果はAIが人間の承認を得ずに修正する
      2. 2回の修正で直せなかった場合は人間に修正できなかった旨を報告する
   4. 人間による動作確認
      1. 問題があれば修正して再度確認を依頼する
   5. 確認OKを受領したらコミットしてPRを案内する（`/create-pr`）

## 完全自律モード（`/dev-auto <issue番号>`）

上記の手順1〜4を1コマンドで自律実行するモード。
**人間のタッチポイントは要件定義フェーズの仕様合意1回のみ。** それ以外の確認はAIのレビュアーエージェントが代理判断する。

```
/dev-auto <issue番号>
  ├── [自動] 進捗確認（途中から再開可能）
  ├── [自動] 仕様生成
  ├── [人間] 仕様確認・合意 ← 唯一のタッチポイント
  ├── [自動] テスト計画作成 → レビュアーエージェントが承認判断
  ├── [自動] テスト実装 → セルフレビュー
  ├── [自動] 実装 → セルフレビュー
  ├── [自動] 実装レビュアーエージェントが承認判断
  └── [自動] コミット・完了報告
```

各フェーズ間の情報受け渡しはissueコメントを介して行う。途中のフェーズからの再開にも対応している。

## 実現方針
- 手順の各フェーズがそれぞれskillとして存在する
  - `create-issue`: issue作成
  - `dev-requirements`: 要件定義（Step 2）
  - `dev-impl-prep`: 実装準備（Step 3）
  - `dev-impl`: 実装（Step 4）
  - `dev-auto`: 完全自律モード（Step 2〜4 を1コマンドで自動実行）
  - `create-pr`: PR作成
- AIが行う各タスクをagentとして実装する
- ドキュメント更新が必要であれば更新する
  - 回す中で生成されるドキュメント
    - 画面一覧
    - 画面遷移図
    - ER図（DB構造を瞬時に把握するため）
    - API一覧
  - これらのドキュメントは要件定義フェーズで更新する（追記・修正どちらもあり得る）
